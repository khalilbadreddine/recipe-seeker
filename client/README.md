# The Recipe Seeker — client

Nutrition-first recipe site: "Find recipes by what your body needs."

## Stack

- **React 19 + Vite 7/8 + react-router-dom v7** (real paths via `BrowserRouter` — never hash routes)
- **Tailwind CSS v4** via `@tailwindcss/vite` (theme tokens in `src/index.css` `@theme`: `forest #1E4633`,
  `cream #FAF5E9`, `ember #E4572E` + tints/shades; Fraunces display + Inter body via Google Fonts)
- **react-helmet-async** for per-route head tags
- **Custom prerenderer** (`scripts/prerender.mjs`) instead of vite-ssg — see below
- Zero paid deps. Dev proxy: `/api` → `http://localhost:3001` (Express API, sibling agent)

## Why not vite-ssg

vite-ssg's React entry (`vite-ssg/react`) was removed in v24+; the latest published version
(28.x) is Vue-only, so it cannot be used with this React codebase. Instead `npm run build` does:

1. `vite build` — client bundle + `dist/index.html` template (with `<!--ssr-head-->` / `<!--ssr-body-->` placeholders)
2. `vite build --ssr src/entry-server.jsx --outDir dist-ssr` — Node SSR bundle
3. `node scripts/prerender.mjs` — renders **every indexable route** (from the same
   `src/data/recipes.json` the pages read, so sitemap and HTML can never disagree) with
   `react-dom/server` + `StaticRouter`, injects head tags into `<head>`, writes
   `dist/<route>/index.html`, plus `sitemap.xml`, `robots.txt` (AI crawlers allowed),
   `llms.txt` and `404.html`. Removes `dist-ssr/` afterwards.

Head-tag mechanics: react-helmet-async v3 on React 19 renders `<title>`/`<meta>`/`<link>` as real
elements via React 19's hoistable-tags support (it no longer populates `context.helmet`), so
`entry-server.jsx` extracts those tags from the rendered markup and the prerenderer moves them
into `<head>`. Verified by grepping `dist/` (see Definition of done in the task brief).

## Scripts

- `npm run dev` — Vite dev server (with `/api` proxy)
- `npm run build` — full static build described above
- `npm run preview` — serve `dist/` locally

## Data contract

`src/data/recipes.json` is generated by the sibling (content) agent. Shape:
`{ site: { name, tagline, canonicalBase }, recipes: [...], nutrients: [...], guides: [...] }`.
**Current status: STUB** — 2 recipes, 7 nutrients, 2 guides, written to the exact contract shape so the
client can be built and verified end-to-end. Swap in the real file (12 recipes) and rebuild; routes,
sitemap and llms.txt regenerate automatically. `SITE_URL` lives in `src/data/site.js` with a TODO to
replace `https://therecipeseeker.com` once DNS is live.

## Key components

`src/components/`: `Seo` (helmet wrapper: title/desc/canonical/OG/Twitter/article times/noindex),
`JsonLd`, `Navbar`, `Footer`, `NutrientBadge`, `RecipeCard`, `NutritionTable` (%DV bars),
`FaqAccordion` (`<details>` so Q&A is in the static HTML), `RatingWidget` (real 1–5 stars in
localStorage per slug — **no fabricated aggregateRating anywhere**), `NewsletterSignup`
(POSTs to `/api/subscribe`), `MedicalDisclaimer`, `Breadcrumbs`.

Pages in `src/pages/`: `Home`, `RecipePage` (full Recipe + BreadcrumbList + FAQPage JSON-LD),
`NutrientHub` (ItemList + BreadcrumbList + FAQPage), `GuidePage` (Article + FAQPage + BreadcrumbList),
`SearchPage` (noindex, client-side nutrient filter), `AboutPage`, `DisclaimerPage`, `NotFound` (noindex).
